# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — dev server (Next.js 16 + Turbopack) at http://localhost:3000
- `npm run build` — production build (also runs `tsc` typecheck + static prerender; use this to verify)
- `npm run lint` — ESLint (`eslint-config-next` core-web-vitals + typescript)
- `npm run start` — serve the production build
- `npm run icons` — re-export every icon the app imports to `icons/*.svg` (+ a README table of where each is used), read straight out of `lucide-react`. Run it after adding or removing a lucide import; don't hand-edit the SVGs.

No test framework is set up. Verify changes with `npx tsc --noEmit`, `npm run lint`, and `npm run build` (all three should be clean).

Two pure-logic files carry their own `assert`-based self-check, run with plain node (no framework, no bundler):

- `RUN_DEMO=1 node src/lib/stage-chat.ts` — field extraction from free text.
- `RUN_DEMO=1 node src/lib/content.ts` — `{{placeholder}}` filling for the authored Markdown in `public/content/`.
- `RUN_DEMO=1 node src/lib/portfolio.ts` — every portfolio derivation, **plus three checks over the real data**: `reconcile()` fails loudly if a card's dates/money and the month-end snapshots in `registry.ts` stop agreeing; `reconcileRecordKpis()` fails if the deep record's Plan & KPI targets and its Monitoring values stop matching; and it fails if any stage field has no `FIELD_GISTS` entry. Run it after editing `registry.ts` or `lifecycle.ts`.

That only works while the data layer stays loadable by node: `src/data/*.ts` import each other **relatively and with the `.ts` extension** (hence `allowImportingTsExtensions` in tsconfig), and `registry.ts` has no value imports at all.

## What this is

A **prototype/demo** UI (no backend, no persistence) for an enterprise AI use-case governance lifecycle. All data is hardcoded; "AI suggest", "save", and submit are mocked client-side. Four routes (`/portfolio` is a fifth that only redirects):

- `/` — intake tracker: kanban board + table views of use-case cards, grouped by stage/owner/priority/due, with scope + search filters. The table view is **one boxed table per group**, each repeating the column header it's read against, with the group's name (14px semibold sans + count pill, matching a board column's header) outside the box — a group header living *inside* one long table has to pretend to be a row, and the column names then sit a long way from the rows at the bottom. Split in two: `src/app/page.tsx` is a thin server page that awaits `searchParams`, and `src/app/tracker-view.tsx` is the client component (`TrackerView`). **Two modes, three levels of switch.** `AppTopBar` sits on the canvas above the panel, inside the panel's own column so the rail's header lands beside it: the **AI Factory** mark in the display serif, a segmented **Registry / Reporting** toggle centred on the column (absolutely — `relative` on that bar is load-bearing, or it centres on the viewport), and the profile. The panel then opens on `PanelViewRow` — `ContentPanel` skips its header row entirely when a route passes nothing into it — carrying the subject (**Use cases** / **Portfolio**, 15px sans semibold), its count, that mode's controls, `New use case` and search, in that order, with search always last. Each depth wears a different shape, because as plain tab strips two of them drew an identical white active pill one row apart: the mode is a **boxed segmented toggle**, Registry's Board · Table are **icon buttons beside the heading**, and Reporting's five readings are a **chip row** on `PanelTabRow` below (`--accent-soft` fill + `--accent-border` on the active chip). Registry keeps search, the attention filter and the grouping menu; Reporting keeps the two scope selects and has no `New use case` — a committee reading the portfolio is not filing an idea. They were one flat row of three tabs (Board · Table · Leadership) until that turned out to put a *display mode* and a whole other reading of the registry at the same level. Params, both forgiving of an unknown value: `?phase=<STAGE_GROUPS key>` narrows the board to one lifecycle phase and shows a removable chip beside the count (Reporting's phase rows link to it), and `?tab=` takes `registry|board|table|reporting|leadership` (the last two are the same mode; `leadership` is what `/portfolio` redirects to).
- `/intake` (`src/app/intake/page.tsx`) — "New use case": a full-screen chat, not a form. Describing the idea *is* the intake; sending hands it to `/detail?idea=…`, whose guided flow asks the follow-ups and fills Ideation. The only route that doesn't use the app shell.
- `/overview` (`src/app/overview/page.tsx`) — a record's landing page: a compact state block, a role-aware "what you need to do" list (ordered yours-first, tagged with whose turn it is), and a lifecycle track — the four phases with per-phase progress, expanding one phase at a time into its stages (each linking to `/detail?stage=n`). Cards on `/` link here. The lifecycle table **scrolls inside its own box** with a sticky column header, so the record block above it never leaves the screen: the box was already the nearest scrollport (it owns the sideways overflow), so while the *wrapper* did the vertical scrolling a `sticky` `thead` measured itself against a port that never moved and rode away with its rows. The header band's rule is an inset shadow on the `th` cells rather than a border on the `tr` — `border-collapse` hands row borders to the table's border model, and a stuck `thead` paints without them.
- **Reporting mode** (`src/app/leadership-views.tsx`, rendered by `TrackerView`) — the committee's read of the whole registry, and one of `/`'s two modes. It was its own route (`/portfolio`, full-width panel, docked assistant) until it moved in here; that route now redirects to `/?tab=leadership`, which is also how a view can be linked to. `LeadershipViews` owns everything below the panel header: a `PanelViewRow` holding its five views (**Overview · Pipeline · Value · Governance · Functions**) and the two scope selects (`Period` narrows the *history*, `Business function` narrows the *records*), then the tiles. Every block is titled with a plain noun. `SummaryPanel` opens Overview and Value with the half of the digest that belongs to it (`healthSummary` / `valueSummary`), authored as Markdown with `summaryProvenance()` in its header. There is no digest modal: a leader shouldn't open a dialog to be told what the page in front of them says. Overview reads numbers → verdict → detail → agenda: a full-width `StatBand` row, then `Portfolio Health` beside `Reading of the quarter`, then `Annual Performance`, then `Waiting on This Committee`. `committeeReading()` returns two things and only two — a `summary` paragraph (the bottleneck folded into it, since it is a *reason* and not an action) and up to **two** `actions` rendered as numbered rows. No bold in either: every figure used to be wrapped in `**`, and eight bold fragments in six lines mark nothing. `Annual Performance` is `MeasureRows` (label · now ▲ / target · bar · share) rather than a five-column table — four measures in four units share only "how far along", which the table made you compute from two of its columns. Composites (`Portfolio Health`, `AI Maturity Index`) are `ScorePanel` — shadcn's radial-shape chart plus the measures it averages; `Adoption Controls` is a radar, `Governance Tier` a donut, and the money-by-function and exposure charts are `HorizontalBars`. Every chart sets `axisLine={false}` where a horizontal `CartesianGrid` already rules the baseline, or the two greys a pixel apart read as a series flat at zero. An empty function scope gets one sentence rather than a grid of zeros.
- **The rail follows the tab.** Registry mode gets `answerAboutPortfolio` + `REGISTRY_HISTORY` and the "start a new use case" door; Reporting gets `answerForLeader` + `LEADERSHIP_HISTORY` (`src/app/leadership-assistant.tsx`) and a thinking beat. Two `useChatSessions` instances, so a thread never switches subject mid-scroll. Search, the attention filter and the grouping menu live in Registry's view row rather than the panel header — a search that filters a kanban you can't see is a control that lies.
- `/detail` (`src/components/document-record/detail-record.tsx`) — the workflow record: the 12-stage lifecycle with a stage-path dropdown, per-stage forms, a guided chat, and a Details/Gates/Comments/Activity side sheet. `?stage=n` deep-links a stage (and treats everything before it as complete). **`?blank=1`** renders `BLANK_STAGES` — the same twelve stages with every value emptied, derived from `STAGES` so a new field can't go missing — for walking the empty state end to end: no stage holds recorded data, the header reads "Untitled use case" with no risk chip, gate or Risk Insight button (each is guarded on a value that no longer exists), and GTAC's AI recommendation doesn't render, because a confident "GO" over empty fields is the one thing that panel must never do. The board's **UC-141** points here; nothing else about that card changed, so the portfolio's `reconcile()` still balances. `StageFormHeader` is **sticky** to the top of the form's scroll container, and it carries that container's top padding (`pt-5`/`pt-6`, with `-mx` bleed to the container's side padding) rather than the container carrying it — padding above a sticky element scrolls away, which left the row's text against the panel edge with the field it had just covered showing through. Sticky because it is the row that says which stage you are filling in and whether you may: on a twelve-field stage it was gone by the third field, taking the stage-path dropdown with it.

**Shell — `src/components/app-shell.tsx`.** Two rows of chrome every route composes: `AppTopBar` (the **AI Factory** mark, an optional centred control, the person) on the canvas *inside the panel's column*, and `ContentPanel` (the rounded floating panel, with an optional footer/status bar). `AppShell` lays out the panel and then the chat rail — fixed 364px, the **last** column, so the object of the conversation keeps the left edge and the assistant sits where a side panel is expected. The record's details sheet is **364px beside the record, inside the panel's column** — record, sheet, chat — so opening it costs the chat nothing; it shared the rail's cell and covered it for a while, which was cheaper in width but hid the assistant behind the panel you open to check a fact you might then want to ask about. It is deliberately *not* a third grid track: `AppTopBar` rides above the record **and** the sheet and stops at the rail's edge, which only works while those two are one column split below the bar. Spanning the bar across the window instead pushes the rail's header down a row and centres the mode toggle on an axis the panel doesn't share. **Every route with a panel passes `AppTopBar`**, including `/overview` and `/detail`: the mark used to lead `ContentPanel`'s header on those two, which gave the app two homes for its identity at two sizes, with the person in a different place on each. The rail header names its own column — **Assistant** — except on `/intake`, which has no panel to carry the mark and so passes `label="AI Factory"`.

`ContentPanel`'s header row is **skipped entirely** where a route passes nothing into it, which is now every route: the tracker opens on `PanelViewRow`, the record routes on the record's own name. `PanelBreadcrumb` therefore has no callers — where a page nests, "up" is a 22px boxed chevron to the left of the record's name (`RecordSummary`'s `back`), with the id beside it in mono and the Details toggle at that line's right edge (`actions`). A breadcrumb row above a 22px title naming the same record was two rows to say one thing.

**Collapsing the rail removes its track.** `railCollapsed` drops the shell to one grid column and the panel takes the whole 376px back (364 + the 12px gap); the rail's section stays mounted under `display:none` so the thread survives, and `RailHeader` renders nothing. The way back is `RailToggle` — an accent-filled `Sparkles` button the route puts beside the person, in the top bar on `/` and in the panel's controls on the record routes. It used to leave a 36px strip holding that button, which read as a second empty column. Note the two one-column cases: `gridColumn: 2` is only pinned when a second track exists, or the *expanded* chat asks for a track the template doesn't declare and the grid invents an implicit one beside an empty `1fr` — a full-width conversation in the right-hand half of the window. Pinning at all is what stops auto-placement sliding the panel into the track the hidden rail left behind. Reporting's own width cap (`RAIL_TRACK` in `leadership-views.tsx`) is `calc(100% - 376px)` for the same arithmetic. The chat rail sits directly on `--shell-canvas`; whitespace, not borders, divides it from the panel.

## Architecture

**Three homes for record data — know which one you're editing:**

0. `src/data/registry.ts` (`USE_CASES`, `PORTFOLIO_ARCHIVE`, `ALL_RECORDS`) — the whole registry, one shallow card each, plus a seeded history layer (dates, investment, benefit, risk tier/level, function, capability, adoption, KPIs, gate history) and `PORTFOLIO_SNAPSHOTS`, six authored month-ends. `AS_OF` is the prototype's "today" — every derivation takes it as an argument, nothing calls `new Date()`. The tracker and the portfolio both read this; `src/lib/portfolio.ts` turns it into KPIs.

**Two parallel data models for the *workflow* — know which one you're editing:**

1. `src/data/document-workflow-form-schema.ts` (`WORKFLOW_STAGES`) — a rich, typed field schema (sections, field types, options, hints, defaults). Drives the intake schema. **NOT** what the `/detail` page renders its stage forms from.
2. `src/data/lifecycle.ts` (`STAGES`) — the array `/detail` and `/overview` both render: 12 stages, each `rows: [label, value][]`, plus `GATES`, `STAGE_INTROS`, `STAGE_GROUPS` (the 4 phases), `RECORD_DETAILS`, and where the record currently sits (`ACTIVE_STAGE_INDEX` / `COMPLETED_STAGE_INDEXES`).

**The record's KPIs are planned in one stage and reported in the next, one row per measure, under identical labels.** Plan & KPI declares `"71% now → 80% target"`, Monitoring reports `"84% of 80% target"`, and `recordKpis(STAGES)` pairs them by label into `{baseline, target, actual, unit, met, progress}` — `progress` runs from the baseline, which is the whole reason a baseline is recorded (`actual / target` flatters any KPI that didn't start at nought). Six of them: Active users, Hours saved a year, Writer satisfaction (CSAT), Return on build cost (ROI), Review time reduction, Summary accuracy. This replaced a single packed `"KPIs and measurement targets"` string that held three targets, no baselines, and named none of the four metrics Monitoring actually reported. Add a KPI to one stage and you must add it to the other — `reconcileRecordKpis()` fails on a target that drifts, a unit that changes, a planned KPI never reported, or one reported but never planned. Note these are *not* the portfolio's `kpiAttainment`, which reads `registry.kpis` for the five **live** cards; the deep record is in Delivery, so it has no portfolio KPIs and nothing is double-tracked today. This mirrors the original reference prototype (`AI Governance Platform.html`, a bundled demo kept outside the repo). When editing stage content, edit `STAGES` here — nothing should keep a second copy.

**`/detail` form rendering is heuristic, driven off `STAGES` `[label, value]` rows:**
- `buildFieldSpec(label, value)` inspects the label/value and picks a `FieldKind`: `currency` (value starts GBP/USD/EUR/£/$/€) → `CurrencyField`; `scale` (`n/m`) → `RatingStepper`; `level` (ordinal sets in `ORDINAL_SETS`, e.g. Low/Medium/High) → `LevelSlider`; `select` (>5 options) → dropdown; short enums → `Segmented`, longer → `RadioGroup`; multi-select → `CardMultiSelect` if label in `CARD_FIELDS` else `ChipMultiSelect`; long text → `SmartTextarea`; else `SmartText`.
- Option lists come from `choiceOptions(label, value)`; multi-select items from `listItems(value)` (splits on `; , ->`). Editing which control a field gets means editing these helpers, not the components.
- **An unfilled field holds `""`, whatever its control.** Single-choice kinds (`toggle`/`tag`/`segmented`/`radio`) used to initialise to `options[0]` so a toggle always showed a selection — which made an untouched stage claim answers nobody gave ("Human oversight: Always", "Data sensitivity: Public", "Duplication check: Not a duplicate", each simply first in its list), counted them toward captured progress, and hid the field's own definition. They start unselected now, like every other kind.
- Every stage — open or completed — renders through `StageFieldsGrid`, which renders the *same* control in both modes (read mode makes it inert and strips its chrome via `.read-field` / `.read-choice`). The **Plan** stage is bespoke (`PlanStageForm`: squad picker, milestone timeline, lockable metrics) registered in `BESPOKE_STAGE_FORMS`; it shares the stage header (`StageFormHeader`) with the grid.
- Two AI reads sit on top of the recorded data, both written from `lifecycle.ts` values (`ai-upgrade:` marks where a model call would go): `GtacRecommendation` (detail-record) puts the call and one line of reasoning above the GTAC fields, and `RiskSummaryModal` (`risk-modal.tsx`) opens off a **Risk Insight** button in the record header's meta row. It used to open off the risk chip, which made the one control on the row look identical to the tag beside it that does nothing — so the chips are states again, and the chip's own hover (which listed the model/ethical/hosting/PII levels) is gone, since the summary's first section says all of it.

**Written documents.** Anything the agent *writes* is one Markdown string rendered by `src/components/document-record/markdown.tsx` (headings, rules, blockquote, bullet/numbered lists, tables, inline bold/italic/code/links — a styling layer, not a parser) inside `markdown-modal.tsx` (a native `<dialog>`). Two callers today: `risk-modal.tsx` (in `markdown-modal.tsx`, a `<dialog>`) and the portfolio's `SummaryPanel` (inline, no dialog). Swap either for a model call and keep the Markdown shape; layout doesn't move.

**Where that copy lives.** The risk summary is authored Markdown in **`public/content/risk-summary.md`**, not a template string in the component — served statically and fetched the first time the modal opens, so wording can be rewritten and reloaded with no build step and nothing to re-run. Its figures are `{{placeholders}}` filled by `fillTemplate()` (`src/lib/content.ts`) from `lifecycle.ts` values, so prose and numbers can't drift; an unknown placeholder **throws** rather than rendering `{{overall}}` to a reader, and the file's own HTML comment documents every key and the section order. Self-check: `RUN_DEMO=1 node src/lib/content.ts`. Why not `import x from "./x.md?raw"` — Turbopack rejects it without a registered loader ("Unknown module type"), and `/overview` is a client component so there's no server boundary to `readFileSync` from either.

**Portfolio derivations — `src/lib/portfolio.ts`.** Every leadership number as a pure function taking its data (`wipByPhase`, `funnel`, `throughput`, `medianCycleDaysByPhase`, `blockers`, `aging`, `gateOutcomes`, `riskMix`, `capacityByOwner`, `moneyByState`, `kpiAttainment`, `headline`, `portfolioDigest`, `reconcile`), the two halves of the ledger keyed by record (`productionRows`, `stoppedRows`), the line that says what a summary was written from (`summaryProvenance`) and the one committed target (`DECISION_TARGET_DAYS`, shared by the stat, the chart's reference line and the pulse part that scores against it). Phase membership is passed in as a `PhaseMap` built from `lifecycle.ts`, so this file keeps no second copy of the lifecycle. Two definitions worth knowing: cycle time counts only records that have **left** a phase (the rest are `open`, and `aging()` names them), and `blockers()` means parked-or-blocked, not rejected — a rejection is a decision, and it shows up in the money buckets and the outcomes ledger instead. The tiles and the chat both read these, so a tile and an answer can't disagree.
- `/intake` *is* the shell in its expanded-rail state: `AppShell railExpanded` + `RailHeader` + the shared `ChatStartScreen`, so its spacing is the same code as the registry's full-width chat. Both header controls return to `/`.

**Reusable field kit — `src/components/forms/fields.tsx`.** All form controls live here (`SmartText`, `SmartTextarea`, `SearchableSelect`, `Segmented`, `RadioGroup`, `RatingStepper`, `LevelSlider`, `ChipMultiSelect`, `CardMultiSelect`, `CurrencyField`, `DateField`, `CompletionMeter`, `SaveStatus`). Every field takes `FieldChrome` props (`label`, `required`, `hint`, `error`, `hideHeader`). Pass `hideHeader` when the label is rendered externally (the `/detail` label-left row layout does this). `DateField` is a custom calendar in a `createPortal` popover (escapes overflow-clipping) — there are no native date inputs.

**Profiles — `src/components/profile.tsx`.** `PEOPLE`, `PersonAvatar`, `ProfileSwitcher`, `initials`. **Every stage owner, gate approver and comment author in `lifecycle.ts` must be a name in `PEOPLE`** — otherwise the record shows people you can never switch to, so "owned by you" can't light up and the lock badge points at a ghost. When `PEOPLE` was trimmed to six, four of the record's cast (Priya N., Marco B., Amara J., Victor H.) were left behind; the twelve stages are now owned by role — Priya Rao takes intake and adoption, Rohan Desai value and KPIs, Dana K. triage and planning, Lena Osei the assessment, Nisha Patel the GTAC call, Noah R. the build. Board *card* owners are a deliberately wider cast (Mira Kapoor, Aarav Mehta, Elena Weber, Daniel Cho) — they render as avatars but aren't profiles you can be. Used by both the home header and the record.

## Styling conventions

**Read `DESIGN.md` first** — it defines the tokens, the 11/12/13/14/15/18/20/40 type scale, the radius + tone system, and the component kit (`src/components/ui/kit.tsx`). Compose from the kit; no raw hex in components.

- Tailwind v4 (`@import "tailwindcss"` in `src/app/globals.css`); no `tailwind.config`. Design tokens are CSS variables in `:root` (`--accent` teal, `--canvas`/`--surface*` warm cream, `--text-*`, `--border-*`, `--status-*`). **Use the token vars** (e.g. `text-[var(--text-label)]`, `bg-[var(--surface-muted)]`) rather than raw hexes where a token exists.
- Typography: `.font-display` = **Fraunces** (editorial serif) for headings + hero values; `.font-serif-body` = lighter Fraunces for prose; default body = **Inter**; `.font-mono` = **Geist Mono** for ids, dates and counts. Pattern: **serif for headings/prose, sans for controls/labels/data.**
- `cn()` (`src/lib/cn.ts`, clsx + tailwind-merge) for conditional classes. Imports use the `@/*` alias (→ `src/`).
- `.no-scrollbar` hides scrollbars on scroll containers (used by the stage path and panels).
